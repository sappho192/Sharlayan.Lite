# Live smoke 검증

## 도구

`tools/Sharlayan.LiveSmoke`는 실행 중인 `ffxiv_dx11` 프로세스에 읽기 작업만 수행하는 opt-in `net8.0` console 도구다. package에는 포함하지 않는다.

검증 항목은 다음과 같다.

- main module의 generated `CHATLOG` signature match 개수
- `InitializationTask` 완료와 `IsInitialized` 상태
- `CHATLOG` memory location 및 최종 pointer 해석
- 첫 poll이 과거 entry를 반환하지 않는 동작
- 후속 poll의 cursor 진행과 신규 entry parsing
- `SharlayanConfiguration.CharacterName` 전달
- polling 중 `OnException` 및 프로세스 종료

채팅 본문, 사용자 이름, 개별 entry timestamp와 byte 길이는 출력하지 않는다. 전체 entry 수, 관찰 code, wrap 수, 최종 cursor만 기록한다.

```powershell
dotnet run --project tools/Sharlayan.LiveSmoke/Sharlayan.LiveSmoke.csproj --configuration Release -- --process-id 9988 --poll-seconds 60
```

`--process-id`를 생략하면 실행 중인 `ffxiv_dx11` 프로세스가 정확히 하나일 때 해당 프로세스를 사용한다.
full smoke는 신규 entry를 최소 1개 요구한다. signature, attach, initialization, 첫 poll만 확인하려면 `--attach-only`를 사용한다.

Hermes v2 candidate를 production 승격 전에 직접 검증하려면 `--manifest`를 사용한다. 이 경로는
일반 library configuration에 노출되지 않는 live-smoke 전용 override이며, 전달한 candidate만 scan한다.
NPC Talk가 열린 상태에서는 `--require-current-talk`로 화면에 표시 중인 name/text를 검증한다.
`--require-last-talk`은 FCS `LastTalkName`/`LastTalkText` 보존값을 별도로 검증한다.
기존 `--require-talk`은 current-first, last-fallback 정책을 검증하는 호환 alias로 유지한다.
기본 로그에는 실제 문자열 대신 source, visibility와 UTF-16 길이만 기록한다. 대사 문자열 출력이
허용된 진단 세션에서는 `--print-talk`을 명시적으로 추가한다.
Manifest 호환성 검사는 hardcoded 값이 아니라 현재 Sharlayan assembly version을 사용한다.

```powershell
dotnet run --project tools/Sharlayan.LiveSmoke/Sharlayan.LiveSmoke.csproj --configuration Release -- `
  --manifest D:\candidate.json --process-id 9988 --attach-only --require-current-talk --print-talk
```

`--print-talk`은 `--require-current-talk`, `--require-last-talk` 또는 `--require-talk`으로 읽은
이름과 본문을 그대로 출력한다. 공유 로그나 CI에서는 사용하지 않는다.

장시간 및 release-gate 검증에는 다음 옵션을 사용한다.

- `--remote-preferred`: public Hermes v2 → verified cache → embedded 순서 사용
- `--latest-uri <https URI>`: remote/cache fallback 검증을 위한 latest endpoint override
- `--resource-cache <directory>`: verified manifest cache 활성화
- `--concurrent-readers <count>` / `--concurrent-calls <count>`: 동일 Reader의 live 다중 thread 호출
- `--minimum-entries <count>` / `--minimum-wraps <count>`: 종료 시 최소 관찰량 강제
- `--required-code <4자리 hex>`: 반드시 관찰해야 하는 chat code, 여러 번 지정 가능
- `--progress-seconds <seconds>`: 장시간 run의 누적 진행 로그 주기

## Sharlayan.Lite 9.1.2 release gate

이번 60초 및 120초 구간에서는 ring wrap이 발생하지 않았다. 2026-07-25 사용자 결정에 따라
single-consumer 장시간 gate는 30분에서 10분으로 조정했다. 10분 PASS는 30분 연속 안정성을
증명하지 않는다. 다음 항목은 모두
Sharlayan.Lite 9.1.2 공개 배포 전 필수 release gate로 처리하며, 각 결과를 이 문서 또는 후속
검증 문서에 기록하기 전에는 package를 공개하지 않는다.

- 1,000개 이상 entry 또는 실제 wrap 전후의 중복과 누락
- 10분 이상 단일 consumer polling
- 여러 thread의 live `GetChatLog` 호출
- say, tell, party, alliance, novice, system 유형의 명시적 fixture
- 관리자 권한 유무에 따른 attach 결과
- upstream Sharlayan 9.1.2와 동일 프로세스 결과 비교
