# Sharlayan.Lite 9.1.4 CHATLOG reset 수정 및 릴리즈

## 배경

9.1.3 공개 직후 final verifier SHA의 extended live run에서 약 360초와 58개 신규
entry를 처리한 뒤 `Invalid chat entry size: -28053`이 발생했다. 실제 이름, 채팅 본문,
프로세스 식별자 및 메모리 주소는 보존하지 않았다.

FFXIVClientStructs의 `LogModule`은 CHATLOG index와 data 저장소를 각각
`StdVector<int>`와 `StdVector<byte>`로 정의한다. 실패 전후 read-only snapshot에서는
index count가 290에서 173으로 감소했지만 allocation capacity는 1066으로 유지됐다.
기존 Reader는 count 감소를 고정 ring wrap으로 해석하고 이전 count부터 capacity까지의
stale slot을 유효한 tail로 읽었다. 이때 감소한 offset 차이가 음수 entry size가 됐다.

## 9.1.4 수정

- index vector의 유효 범위를 allocation capacity가 아니라 current count로 제한한다.
- count 감소나 vector storage/capacity 변경을 reset으로 처리한다.
- reset 시 stale tail을 반환하지 않고 현재 vector 끝으로 cursor를 re-prime한다.
- pointer/index/data snapshot을 읽기 전후로 비교하고 변경되면 최대 3회 재시도한다.
- 실패한 snapshot에서 읽은 entry는 폐기해 중복 반환하지 않는다.

이 정책은 reset 경계에서 과거 entry를 추측해 반환하는 대신 해당 경계의 신규 entry를
건너뛸 수 있는 fail-safe 정책이다. 잘못된 크기의 할당이나 손상된 entry 반환보다 cursor
재동기화를 우선한다.

## 회귀 검증

- 관찰된 `previousIndex=290`, `currentCount=173`, `capacity=1066` 상태를 fixture로 재현한다.
- count 이후 stale capacity slot을 읽지 않는지 확인한다.
- index snapshot 변경 시 cursor commit 전 재시도하는지 확인한다.
- data snapshot 변경 시 첫 시도 entry가 중복 반환되지 않는지 확인한다.
- `net8.0`과 `net10.0`에서 전체 테스트를 실행한다.
- 모든 library target framework를 Release로 빌드한다.
- final verifier SHA에서 CHATLOG live polling과 reset/re-prime 증거를 수집한다.

## 릴리즈 절차

9.1.3 publish workflow는 nupkg push가 sibling snupkg를 자동 게시한 뒤 같은 snupkg를
명시적으로 다시 게시해 HTTP 409로 종료됐다. 9.1.4부터 nupkg push에는 `--no-symbols`를
사용하고 검증된 snupkg를 별도 명령으로 정확히 한 번 게시한다.

```powershell
dotnet run --project tools/Sharlayan.ChatResources.Generator/Sharlayan.ChatResources.Generator.csproj --configuration Release --no-launch-profile
git diff --exit-code -- Sharlayan/Resources/GeneratedChatResources.g.cs
dotnet restore Sharlayan.sln
dotnet build Sharlayan.sln --configuration Release --no-restore --nologo
dotnet test Sharlayan.Tests/Sharlayan.Tests.csproj --configuration Release --no-build --no-restore --nologo
dotnet pack Sharlayan/Sharlayan.csproj --configuration Release --no-build --no-restore --nologo --output artifacts/packages-9.1.4
.\tools\Verify-Package.ps1 -PackageDirectory .\artifacts\packages-9.1.4 -ExpectedPackageVersion 9.1.4 -ExpectedRepositoryCommit <final-verifier-sha>
.\tools\Verify-PackageConsumer.ps1 -PackageDirectory .\artifacts\packages-9.1.4 -ExpectedPackageVersion 9.1.4 -ExpectedRepositoryCommit <final-verifier-sha>
```

먼저 release workflow를 `publish=false`로 실행해 artifact를 검증한다. final SHA live gate와
NuGet version 부재를 다시 확인한 뒤에만 `publish=true`를 실행한다. Production 환경 승인,
OIDC `NuGet/login`, flat-container/registration indexing 및 nuget.org 전용 신규 cache
consumer 검증을 유지한다.
